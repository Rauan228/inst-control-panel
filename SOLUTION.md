# Устройство фермы

Документ для разработчика, который будет вести проект: как устроено, что где
лежит и как это эксплуатировать.

## Слои

1. **Идентичность** (`IdentityFactory`) — имя, фамилия, ник, дата рождения,
   почта. Данные согласованы между собой: ник строится из той же пары
   имя-фамилия, что уходит в профиль.
2. **Транспорт** — два канала:
   * `autoreg.py` — браузер (Playwright + Chromium, живая страница, куки);
   * `api_reg.py` — мобильный API (`aiograpi`), запросы с device-профилем,
     подписью и app-заголовками. Формы в браузере нет.
3. **Гейт** (`HumanGate`) — текстовый капча-экран, номер, SMS, селфи,
   апелляция. В API-канале проходится в webview с сессией клиента.
4. **Сессии** — `cookies/<user>_<ts>.json`, база `accounts.json`,
   журнал `audit.jsonl`.
5. **Управление** — `import_accounts.py` (приём аккаунтов), `comments.py`
   (прогрев, публикация, проверка видимости), `check_accounts.py`
   (статусы, дожим гейта, подписка).

## Потоки

**Регистрация.** Прокси на аккаунт -> форма -> код из почты по IMAP ->
капча -> номер и SMS -> селфи -> апелляция -> подписка на целевой профиль ->
сессия и учётка в базу.

**Импорт.** `user:password` или `user:/path/cookies.json` -> проверка входа ->
сессия в `cookies/` -> запись со статусом `alive`.

**Комментарии.** Сессия -> прогрев профиля -> публикация -> пауза ->
проверка видимости с анонимной сессии -> отчёт по статусам.

## Каналы: когда что

- основной — API: меньше признаков автоматизации, дешевле по трафику;
- браузерный — запасной: нужен, если API-флоу меняется на стороне Meta;
- импорт — когда аккаунты приходят из внешнего источника, регистрация
  не нужна вообще.

## Проверено замерами

Исключены как причины отказов модерации: тип прокси (мобильные,
резидентские, прямой IP), виртуальные номера, домен и шаблон почты,
интервал между аккаунтами. Гейт и форма проходят на любом из вариантов
стабильно.

Узкое место — доверие Meta к аккаунту: номер и устройство. На реальном
номере апелляция проходит, на дешёвых виртуальных — нет.

## Эксплуатация

- пул прокси sticky: один эндпоинт на аккаунт, переиспользование не раньше
  `PROXY_STICKY_HOURS`;
- капча: платный решатель, локальный OCR — фолбэк;
- SMS: провайдер либо ручной номер с файлом-кодом;
- аккаунты расходники: пополнять пул, слетевшие сессии перелогинивать
  по паролю, мёртвые исключать;
- проверка статусов — по расписанию, комментарии — порциями по 10–20
  аккаунтов с паузами.
